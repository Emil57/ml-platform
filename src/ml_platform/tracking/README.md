# MLflow Tracking

The tracking module provides a reusable interface for experiment tracking using [MLflow](https://mlflow.org/).

It abstracts MLflow configuration and exposes a simple API for logging:

* Experiment runs
* Parameters
* Metrics
* Artifacts

## Responsibilities

The `ExperimentTracker` is responsible for:

1. Configuring the MLflow tracking and registry URIs.
2. Creating or retrieving experiments.
3. Starting MLflow runs.
4. Logging training parameters.
5. Logging evaluation metrics.
6. Logging local artifacts generated by the ML Platform.

The tracking layer does not manage local artifact persistence. That responsibility remains with `ArtifactManager`.

## Usage

```python
from ml_platform.tracking import ExperimentTracker

tracker = ExperimentTracker(
    experiment_name="ca-house-prediction",
)

with tracker.start_run():
    tracker.log_params(
        {
            "random_state": 42,
            "n_estimators": 100,
        }
    )

    tracker.log_metrics(
        {
            "rmse": 0.52,
            "r2": 0.81,
        }
    )
```

Artifacts generated by `ArtifactManager` can also be logged:

```python
model_path = artifact_manager.save_model(model)

with tracker.start_run():
    tracker.log_artifact(model_path)
```

## Configuration

MLflow configuration is provided through the platform settings.

The default local configuration uses SQLite:

```text
sqlite:///mlflow.db
```

The configuration can be overridden through environment variables:

```text
ML_MLFLOW_TRACKING_URI
ML_MLFLOW_REGISTRY_URI
ML_MLFLOW_EXPERIMENT_NAME
```

For example:

```text
ML_MLFLOW_TRACKING_URI=http://localhost:5000
ML_MLFLOW_REGISTRY_URI=http://localhost:5000
ML_MLFLOW_EXPERIMENT_NAME=ca-house-prediction
```

## Testing

The tracking tests use isolated temporary SQLite databases so that tests do not depend on the developer's local MLflow database.

Run the tracking tests with:

```bash
uv run pytest src/ml_platform/tracking/test_tracker.py -v
```

Run the complete test suite with:

```bash
uv run pytest
```

## Architecture

```text
Training Pipeline
       │
       ├── Parameters
       ├── Metrics
       └── Artifacts
              │
              ▼
      ExperimentTracker
              │
              ▼
            MLflow
          ┌────┴────┐
          │         │
       Backend   Artifacts
        Store      Store
```

The tracking layer is intentionally independent from the training and artifact-management implementations so that MLflow can be replaced or reconfigured without changing the rest of the platform.
